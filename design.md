# Raketa — Design Guidelines

Дизайн-система продукта. Любое визуальное изменение — новый экран, новая
кнопка, новая панель — должно быть проверено против этого документа. Если
что-то не вписывается ни в одно правило ниже, сначала обновите этот файл,
а не делайте разовое исключение в коде.

Философия в одной строке: **native-adjacent, не native-identical.**
Raketa не притворяется системным приложением с эффектом стекла — у неё
своя, узнаваемая, полностью непрозрачная светлая идентичность, но с
дисциплиной macOS в основе: те же отступы, та же типографическая шкала, та
же логика плотности, что и в системных панелях. Это ощущается «как дома» на
10.13, не выглядя дженериком.

---

## 1. Принципы (в порядке приоритета)

1. **Прозрачность контента важнее эффектности.** Пользователь должен за
   0.5 секунды понять: подключено или нет, какой сервер выбран, что делает
   каждая кнопка. Никаких неоднозначных иконок без подписи или tooltip.
2. **Минимализм — это отсутствие лишнего, а не отсутствие деталей.**
   Каждый элемент, который есть на экране, должен объяснять себя сам.
   Лучше одна ясная кнопка с текстом, чем три иконки без подписей.
3. **CPU-бюджет — часть дизайна, не только часть кода.** Никаких
   анимаций частиц, теней с блюром, живых градиентов, которые
   перерисовываются на каждый кадр. Статичные слои (`CALayer`) с
   заранее вычисленным `backgroundColor` — вот и весь бюджет на эффекты.
4. **Плотность как в системных панелях 10.13, не как в вебе.** Компактно,
   но не тесно. Каждое число отступа ниже — не эстетический выбор, а
   прямая калька с HIG macOS 10.13.

---

## 2. Цветовая палитра

Основа — «мягкий небесно-голубой». Не воспроизводит системный `#007AFF`
дословно (это акцент для *системных* элементов), а формирует свою,
узнаваемую идентичность бренда поверх системной логики.

| Токен       | HEX       | Назначение |
|-------------|-----------|------------|
| `rkBG`      | `#E0EDFA` | Фон окна целиком |
| `rkSurface` | `#CCE3F5` | Хедер, нижняя панель — на 1 тон темнее фона |
| `rkCard`    | `#D4E8F7` | Всплывающие панели (Telegram-панель) — между BG и Surface |
| `rkBorder`  | `#9EC7EB` | Разделители, границы кнопок и полей |
| `rkText`    | `#1A1A1A` | Основной текст — не чистый чёрный, тёплый графит |
| `rkSub`     | `#666666` | Вторичный текст, неактивные состояния |
| `rkAccent`  | `#1A66C7` | Ссылки, моноширинные данные, акцентные детали |
| `rkGreen`   | `#148C38` | Состояние «подключено» |
| `rkOrange`  | `#BF610A` | Предупреждение (не критично, требует внимания) |
| `rkRed`     | `#B81414` | Ошибка |
| `rkBtn`     | `#B8D6F0` | Заливка второстепенных кнопок |

**Правила использования:**
- Никакой прозрачности (`alpha < 1.0`) на фоновых слоях. Единственное
  исключение — временная подсветка состояния (например, лёгкая заливка
  активной иконки, `alpha ≈ 0.15`), и то через `CALayer.backgroundColor`,
  не `NSVisualEffectView`.
- Не добавлять новые цвета без крайней необходимости. Если нужен ещё один
  статус — сначала проверить, подходит ли `rkOrange`/`rkRed`/`rkGreen`.
- Текст всегда `rkText` или `rkSub` — никогда чистый `#000000` или
  `#FFFFFF`. Мягкий контраст — часть идентичности.
- `rkAccent` — единственный «яркий» цвет в интерфейсе кроме статусов.
  Если тянет добавить второй акцентный цвет — это сигнал остановиться и
  спросить, а не добавлять.

## 3. Типографика

Системный шрифт (SF Pro через `[NSFont systemFontOfSize:weight:]`) везде,
кроме единственного места, где сознательно используется другой:

| Кегль | Вес | Где |
|---|---|---|
| 14pt | Semibold | Заголовок приложения в хедере |
| 13pt | Regular | Базовый текст: кнопки, dropdown, поля ввода |
| 11pt | Medium/Regular | Вторичный текст: секционные лейблы, статус, второстепенные кнопки |
| 10pt | Regular (Menlo) | Моноширинные технические данные (IP, порт, секрет) |
| 9pt | Regular/Semibold | Микро-текст: версия, панель Telegram заголовок |
| 9pt | Light (HelveticaNeue-Light) | Только строка copyright/подписи внизу, с `NSKernAttributeName: 0.8` |

**Правила:**
- Это точная калька шкалы HIG macOS 10.13 (13/11/9pt), не произвольные
  числа. При добавлении нового текстового элемента — выбирать кегль из
  этой таблицы, не изобретать новый.
- Единственное отклонение от системного шрифта — `HelveticaNeue-Light`
  для подписи внизу окна. Не расширять список кастомных шрифтов без
  необходимости — каждый доп. шрифт это дополнительная зависимость и
  риск деградации на разных версиях macOS.
- Моноширинный (`Menlo`) — только для данных, которые пользователь может
  захотеть скопировать вручную (IP, порт, секрет). Не использовать Menlo
  для обычного UI-текста.
- Кернинг (`NSKernAttributeName`) применяется точечно — только там, где
  дефолтный трекинг реально ломает читаемость на маленьком кегле (было
  замечено на подписи 9pt). Не применять глобально.

## 4. Сетка и отступы

Строгая калька с HIG macOS 10.13:

| Токен | Значение | Правило |
|---|---|---|
| Внешние поля окна | **20pt** | От любого края окна до первого элемента |
| Между независимыми группами | **12pt** | Между секциями (Подписка → Сервер → Статус) |
| Между связанными элементами | **8pt** | Между лейблом и его контролом, между кнопкой и соседней кнопкой одного назначения |
| Внутри плотной группы | **4pt** | Между мелкими однотипными элементами (не используется пока, зарезервировано) |

**Правила:**
- Ширина окна: **300pt** — не менять без крайней необходимости
  (это ширина, проверенная и утверждённая; больше — теряется
  компактность «popover», меньше — текст начинает переноситься).
- Высота — плавающая величина, зависящая от контента, но каждая секция
  должна укладываться в отступы выше. Не добавлять «воздух ради воздуха»
  сверх 12/8pt.
- Разделители (`sep`) — 1pt, цвет `rkBorder`, всегда между логически
  разными секциями, никогда внутри одной.

## 5. Компоненты

### Кнопки
Три типа, три чётких роли — не смешивать:

1. **Первичная кнопка действия** (`primary: YES`) — системный
   `NSBezelStyleRounded`, 13pt текст. Используется один раз на экран для
   главного ожидаемого действия («Добавить ключи»).
2. **Вторичная кнопка** (`primary: NO`) — тот же bezel, но не
   единственная в своём ряду. Используется для «Логи», «Выход»,
   переключателей.
3. **Иконка-кнопка** (без подписи, например ↻ или ✈) — **никогда**
   `NSBezelStyleRounded`. Системный bezel на 10.13 обрезает/скрывает
   Unicode-глифы при маленьком размере. Всегда: `bordered = NO` +
   явный `CALayer` (`cornerRadius`, `borderWidth`, `backgroundColor`) +
   `attributedTitle` с явным шрифтом и цветом. Обязателен `toolTip`.

Главная кнопка подключения (ВКЛ/ВЫКЛ) — единственный элемент с
кастомной капсульной формой (`cornerRadius = height / 2`). Это
единственное место, где допустима нестандартная форма кнопки — она
единственная в приложении и заслуживает визуального веса главного
действия.

### Поля ввода и dropdown
Заливка `rkSurface`, `cornerRadius` 5–6pt, `borderWidth` 1pt цвета
`rkBorder`. Без фокус-ринга (`NSFocusRingTypeNone`) — фокус подсвечивается
через сам цвет рамки, не через системное кольцо (конфликтует с плоской
эстетикой).

### Индикатор статуса
Цветная точка (`7×7pt`, `cornerRadius 3.5`) + текст того же цвета.
Цвет = семантика: `rkSub` (нейтрально/ожидание), `rkGreen` (успех),
`rkOrange` (предупреждение), `rkRed` (ошибка). Не вводить новых
цветов-состояний без крайней нужды — четырёх достаточно для всех
сценариев VPN-клиента.

### Всплывающие панели (пример: Telegram)
Отдельный фон `rkCard` (на тон темнее `rkBG`, но светлее `rkSurface`) —
создаёт визуальную иерархию «эта панель — временная, вложенная», не
сливаясь ни с основным фоном, ни с хедером/футером. Открывается сдвигом
существующих элементов, не перекрытием (`z-order` overlay). Всегда
обновлять `preferredContentSize` попапа при изменении высоты — иначе
NSPopover не перерисуется корректно.

## 6. Иконография

- Один источник — **эмодзи/Unicode-символы**, не растровые иконки и не
  SF Symbols (SF Symbols недоступны на 10.13 как публичный API — появились
  в 11.0). Это осознанное ограничение, а не временный костыль.
- Используемый набор: 🚀 (бренд), ＋ (добавить), ↻ (обновить), ✈
  (Telegram), ⚡ (deep-link действие), ○/● (состояние вкл/выкл), ✓
  (подтверждение).
- Каждый новый символ перед добавлением проверять на совместимость с
  10.13 — не все Unicode-блоки рендерятся одинаково на старых версиях
  системного шрифта. При сомнении — тестировать на реальной машине или
  выбирать символ из широко поддерживаемого диапазона (Miscellaneous
  Symbols, Dingbats — безопасные блоки).
- Иконка приложения (`AppIcon.svg` → `.icns` при сборке) — белая «R» на
  радиальном голубом градиенте, скругление 22.5% (стандарт macOS для
  иконок приложений). Не менять форму/пропорции без явного запроса —
  единственная иконка бренда, узнаваемость важнее вариативности.

## 7. Анимация и обратная связь

- **Никаких `CABasicAnimation`, `NSAnimationContext` с длительностью
  больше мгновенной подсветки состояния.** Единственная допустимая форма
  «анимации» — мгновенная смена `title`/`backgroundColor` с последующим
  возвратом через `dispatch_after` (пример: кнопка «Скопировано» на
  1.2–1.5 секунды). Это не анимация в смысле кадров — это временная смена
  состояния, дешёвая для CPU.
- Обратная связь на действие пользователя должна быть видна **в течение
  одного кадра**, не через плавный переход. Мгновенная смена цвета текста
  статуса — предпочтительнее, чем fade-in/fade-out.
- Никаких спиннеров/индикаторов загрузки с постоянной перерисовкой. Текст
  статуса («Загрузка...», «Обновление серверов...») — достаточная
  обратная связь и не требует таймера перерисовки.

## 8. Голос и тон текста интерфейса

- Русский язык, неформальный, но не разговорный. Без канцелярита
  («произведена попытка подключения» — нет; «Запуск...» — да).
- Короткие статусы: 2–4 слова там, где это возможно
  («Готов к работе», «Серверов: 5», «Ядро упало — нажми ВКЛ»).
- Ошибки — по существу, с подсказкой к действию, не просто констатация
  факта («Сначала добавьте ключи», не «Ошибка: ключи отсутствуют»).
- Никакого излишнего дружелюбия/маскота-стиля кроме единственной
  сознательной детали — подписи «Ради вас старался Пашенька» внизу окна.
  Это осознанное исключение, часть идентичности продукта, не образец для
  расширения тона остального интерфейса.

## 9. Чек-лист перед добавлением нового элемента UI

Перед тем как добавить что-то новое на экран, пройти по списку:

- [ ] Цвет взят из палитры в разделе 2, не придуман новый HEX
- [ ] Кегль текста взят из таблицы в разделе 3
- [ ] Отступы от соседних элементов — 20 / 12 / 8pt по разделу 4
- [ ] Если это кнопка-иконка без подписи — использован паттерн
      `bordered=NO` + `CALayer`, не `NSBezelStyleRounded`
- [ ] Если элемент временный/всплывающий — обновлён
      `preferredContentSize`
- [ ] Нет анимаций длительностью больше визуальной подсказки состояния
- [ ] Протестирована высота/переносы текста на кегле из таблицы (не «на
      глаз»)
- [ ] Новый элемент не требует постоянного таймера или фонового опроса

Если хотя бы один пункт не выполняется — сначала решить, обновлять ли
этот документ, а не тихо нарушать правило в коде.
