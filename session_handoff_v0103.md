### Что было сделано в этой сессии (поверх v0.10.0)

#### v0.10.1 — `patch_raketa_0101.py`
Три независимых изменения, одним релизом:

**Roadmap #2.1 — таймаут загрузки подписки**
- `downloadURL:` использовал `[NSURLSession sharedSession]` с дефолтным
  60-секундным таймаутом. На DPI-заблокированных сетях это выглядело
  как "зависший" UI на минуту.
- Fix: `NSMutableURLRequest` с `timeoutInterval = 10.0`. Отдельное
  сообщение `@"Сервер не отвечает"` для `NSURLErrorTimedOut` vs
  `@"Ошибка сети"` для остальных ошибок.
- Место в коде: метод `downloadURL:` (~строка 328).

**Roadmap #2.6 — проверка бинарника sing-box перед привилегированным запросом**
- `pathForResource:@"sing-box"` возвращает `nil` без ошибки при
  повреждённой сборке. Nil тихо попадал в shell-строку, пользователь
  тратил пароль администратора, потом fail.
- Fix: `fileExistsAtPath:` до записи конфига и до AppleScript-вызова.
  Переменная `singBoxBin` объявляется здесь, ниже по методу
  `NSString *bin = singBoxBin;` (переиспользование, не второй lookup).
- Место в коде: начало `startVPN` (~строка 479), сразу после `if (!outbound) return;`.

**GUI spacing pass (запрос этой сессии)**
- Прогнал реальные `top`/`height` каждого элемента `loadView` через
  расчёт зазоров, сравнил с авторскими комментариями в коде.
- Кнопка "Подключиться": была `top:152`, в комментарии `// Connect button (168–204)`.
  Drift = 16pt. Заезжала на status row, не стыковалась с разделителем.
  Исправлено: `top:168`.
- Section labels: `ПОДПИСКА` и `СЕРВЕР` имели разный зазор от разделителя
  (11pt vs 12pt) и формально пересекались рамкой со следующей строкой на 2px.
  Сдвинуты вверх на 3pt каждый (`44→41`, `96→92`) — без сдвига того, что
  ниже, ноль каскада.

**Финальная таблица зазоров loadView (v0.10.1+, без изменений в 0.10.2/0.10.3):**

#### v0.10.2 — `patch_raketa_0102.py`

**Roadmap #2.2 — валидация outbound перед записью config.json**
- До фикса: единственная проверка перед `writeToFile:` и привилегированным
  запуском — "нашёлся ли outbound по тегу". `server` мог быть `""`,
  `server_port` — вообще отсутствовать или иметь неожиданный тип.
- Два источника плохих данных: `parseVless:` (пустой host в URL) и
  `parsedJSON:` (JSON-подписка без валидации полей).
- Без проверки: плохой конфиг писался на диск, пользователь тратил пароль,
  sing-box сразу падал, через 1.5с — "Ядро не запустилось".
- Fix: проверка `server` (non-empty NSString после trim) и `server_port`
  (1–65535) с `isKindOfClass:` guards перед любым другим действием в методе.
  Сообщение: `@"Некорректные данные сервера"`.
- Место: в `startVPN`, после проверки 2.6 (singBoxBin), до `cfg = @{...}`.

#### v0.10.3 — `patch_raketa_0103.py`

**Roadmap #2.3 — `chmod 600` на `config.json` после каждой записи**
- `writeToFile:atomically:YES` создаёт temp-файл + rename — права берутся
  из umask (обычно `644`, world-readable). Поскольку конфиг перезаписывается
  при **каждом** подключении, права сбрасывались бы заново каждый раз.
- `config.json` содержит VLESS UUID и Reality-ключи всех серверов.
- Fix: `[[NSFileManager defaultManager] setAttributes:@{NSFilePosixPermissions: @0600} ...]`
  сразу после `writeToFile:`. Без NSTask, без shell-out — один Foundation вызов.
- `sing-box` читает файл как root (`do shell script ... with administrator
  privileges`) — root обходит POSIX permission bits полностью, `0600` его
  не блокирует. Блокирует только других локальных пользователей.
- Место: в `startVPN`, строка сразу после `[cfgData writeToFile:self.configPath atomically:YES];`.

## Важное про build.yml (расхождение с handoff.md)

`handoff.md` §7 описывает старый flow: `git tag` + `git push --tags` → триггер
сборки. **Это устарело.** С v0.10.0 `build.yml` — `workflow_dispatch`-only:
- Никакого `push: tags:` триггера нет.
- Версия вводится вручную в поле при запуске workflow.
- Сам workflow создаёт тег из введённого значения.

Процесс деплоя (актуальный):
```bash
git add -A
git commit -m "..."
git push origin main
# GitHub → Actions → "Build Raketa" → Run workflow → version: X.X.X
```

§7 в `handoff.md` стоит обновить при случае.

## Открытые вопросы из этой сессии

### Двойной туннель (v2rayU + sing-box)
Пользователь видел в Activity Monitor два процесса одновременно. Диагноз:
скорее всего, v2rayU просто не был закрыт как приложение — его ядро
продолжало работать в фоне (keepalive/reconnect), хотя системные прокси
уже перезаписаны Raketa. Raketa не знает о v2rayU и не может им управлять.

Рекомендации по диагностике были даны пользователю:
```bash
ps aux | grep -i v2ray
launchctl list | grep -i v2ray
ls ~/Library/LaunchAgents/ | grep -i v2ray
```
и команды для полного удаления v2rayU. Результат проверки неизвестен —
уточни в начале следующей сессии, если это всё ещё актуально.

## Рабочие правила (установленные до этой сессии, подтверждены)

- Думаем и пишем код на **английском**. UI-строки и git-коммиты — на **русском**.
- Delivery format: один полный Python-скрипт на изменение. Бэкап до правки,
  проверка совпадения old-текста перед записью (guard против double-patch),
  git-команды в конце вывода.
- Тестировать end-to-end (запуск скрипта на реальных файлах), не только
  `py_compile`. Проверять diff после, не только "запустилось без ошибок".
- Диагноз (root cause, 1–2 предложения) до кода. Хирургически — не трогать
  рядом стоящий код "пока зашли". Комментарии в ObjC объясняют *почему*,
  не *что*.
- Не трогать: VLESS/Reality/routing-логику, кредит в UI, общий визуальный
  стиль — без явного запроса.
- macOS 10.13 (High Sierra) — основная цель. `do shell script ... with
  administrator privileges` выполняется без контролирующего терминала.
  CPU-нагрузка — приоритет выше визуального лоска.
